## 1. Alcance y convenciones

Este documento cataloga las reglas de negocio que el código hace cumplir en los doce catálogos maestros: Unidades de medida (`UDM`), Jerarquías de unidades (`JER`), Laboratorios (`LAB`), Ingredientes activos (`ING`), Medicamentos (`MED`), Presentaciones de venta (`PRE`), Formulaciones clínicas (`FOR`), Proveedores (`PRV`), Aseguradoras (`ASE`), Catálogo DIGEMID (`DIG`), Pacientes (`PAC`) y Profesionales de salud (`PRO`).

Las reglas transversales (aislamiento por empresa, borrado lógico, concurrencia, saneamiento de texto, límites genéricos de importación y exportación, autenticación y permisos) las documenta la parte A con los prefijos `GEN`, `IMP`, `AUT` y `ROL`. Aquí solo se citan como «ver reglas GEN/IMP en la parte A» cuando una regla de catálogo depende de ellas.

**Abreviaturas de ruta** usadas en la columna «Dónde se aplica» (todas son rutas reales; solo se acorta el prefijo):

| Abreviatura | Ruta completa |
|---|---|
| `APP/` | `sofia-apis/src/SOFIA.Application/` |
| `DOM/` | `sofia-apis/src/SOFIA.Domain/Entities/` |
| `API/` | `sofia-apis/src/SOFIA.API/Controllers/` |

**Cómo leer las tablas**

- Una regla agrupa todas las ubicaciones donde se hace cumplir el mismo comportamiento (validador, entidad, handler, índice). Cuando cada ubicación devuelve un código distinto, la columna «Código de error» los lista en el mismo orden.
- «Sin traducción» significa que ninguna pantalla asocia ese código a un texto propio; se indica qué texto termina viendo el usuario.
- «Inalcanzable por API» significa que la comprobación existe en el código pero otra anterior (normalmente el validador) responde antes con la misma condición.

## 3. Cómo resuelve el SPA un código de error

1. **No hay un traductor global de códigos.** El único interceptor (`sofia-web-spa/src/app/core/interceptors/auth.interceptor.ts:23-49`) solo trata el 401 (renueva el token) y el 403 con código `Auth.CambioClaveRequerido`; cualquier otro error se propaga tal cual a la pantalla.
2. **`ErrorNotifierService` solo muestra el aviso** (`sofia-web-spa/src/app/core/services/shared/error-notifier.service.ts:26-46`): `showError` abre un aviso con el texto que recibe; `showServerError` muestra el texto amigable y, si la respuesta trae `traceId`, la referencia para soporte. No traduce códigos.
3. **Cada pantalla de detalle traduce al guardar** con `saveErrorKey(err, SAVE_ERROR_KEYS, fallback)` (`sofia-web-spa/src/app/shared/utils/save-error-key.util.ts:11-15`). El orden es: mapa propio de la pantalla (`SAVE_ERROR_KEYS`) → códigos de base de datos (`Db.Duplicado` → `errors.dbDuplicado`, `Db.ReferenciaInvalida` → `errors.dbReferenciaInvalida`, `Db.ValorInvalido` → `errors.dbValorInvalido`; `save-error-key.util.ts:4-8`) → mensaje genérico de la pantalla.
4. **El mensaje en inglés del backend (`detail`) nunca se muestra** en las pantallas de este documento: ninguna lee `error.detail` (búsqueda sin resultados en `sofia-web-spa/src/app/pages/` de los doce módulos y en `shared/`). Un código sin entrada en el mapa de la pantalla termina en el mensaje genérico de la operación.
5. **Al eliminar**, cada pantalla decide por su cuenta (normalmente por el código HTTP 409); se indica en cada módulo.
6. **Carga masiva** (`sofia-web-spa/src/app/shared/components/carga-masiva-page/carga-masiva-page.component.ts:17-34`): `cargaMasivaErrorKey` traduce `CargaMasiva.Archivo.Invalido`, `CargaMasiva.Archivo.ExcedeDescompresion`, `CargaMasiva.Filas.Excedidas`, `Request.TooLarge` y el HTTP 413; un código `CargaMasiva…Command.Rows` se muestra como «demasiadas filas» y un código `CargaMasiva…Command.Rows[…` como «filas inválidas». Cualquier otro fallo usa `carga-masiva.preview-error` o `carga-masiva.save-error`.
7. **Errores por fila de la vista previa**: el backend devuelve por fila una lista de `{ code, field, params }` (`sofia-apis/src/SOFIA.Application/Common/Excel/ValidationError.cs:3-7`) y el SPA los pinta con la clave `carga-masiva.validation.<code>` pasando `field` y los parámetros (`carga-masiva-page.component.html:92-96`, `carga-masiva-page.component.ts:175-177`). El nombre del campo se muestra tal como lo envía el backend (por ejemplo `codigo`), sin traducir.
8. **Validación previa en el formulario**: los formularios de detalle repiten parte de las reglas con validadores de Angular; cuando existen, la petición no sale y el usuario ve el mensaje del campo (por lo general `general.errors.required`).

## 5. Jerarquías de unidades (`JER`)
